# pwebbundle — the CAP-6 app.pwb bundler

Packs an **already-built** frontend dist into the deterministic
`app.pwb` release container (a plain ZIP read by the CAP-4
`TZipAssetStore`). It never compiles a frontend.

```
pwebbundle <distdir> <out.pwb> [--min-runtime=X.Y.Z]
           [--max-asset-bytes=N] [--include-sourcemaps]
pwebbundle --verify <bundle.pwb> [iterations]
```

Layout of the produced archive — all entries under canonical logical
names (forward slashes, exact case), globally sorted by name bytes,
fixed DOS timestamp, fixed deflate level, no extra fields, so identical
logical input yields **byte-identical archives** across time and
machines:

```
app.pwb
├── manifest.json      generated by the bundler (input may not have one)
├── index.html         required — the bundle must be bootable
└── assets/...         the dist tree, verbatim bytes
```

`manifest.json` is exactly the ratified compatibility block
(`spec-phase-6` D6; see also `docs/kernel.md` "Wire"):
`{"pweb":{"protocol":N,"minRuntime":"X.Y.Z"}}` — `protocol` is stamped
from `PWEB_PROTOCOL_VERSION`, `minRuntime` defaults to
`PWEB_RUNTIME_VERSION` (strict numeric `X.Y.Z` only). The manifest
grants nothing: the loader reads only this block, and capability-like
fields are inert.

Validation before a single byte is written: every entry name passes the
CAP-4 canonical-path validator; duplicates, Unicode-10.0-case-fold
collisions (ratified D1) and file/directory collisions reject; secret
and dev artifacts (`.env`/`.env.*`, key/cert extensions, `.git*`,
`node_modules`, lockfiles, `*.pas`, `.DS_Store`, `Thumbs.db`) are hard
errors by name; `*.map` is excluded with a logged skip unless
`--include-sourcemaps`; assets above the ratified 32 MiB ceiling
(override: `--max-asset-bytes`) fail the build naming the blob-plane
escape route. The output is written to a temp sibling, re-opened
through the **production loader** (raw stored-name byte compare
included), then atomically replaces the previous bundle — which
survives intact on any failure.

`--verify` re-opens an existing bundle through the production loader
with this runtime's facts and reads `index.html` + `manifest.json`;
the optional iteration count repeats the cycle for observational
timing.

Build (assets layer + RTL-only rpc constants — no webview, no mORMot
REST; `test/cap6/build_cap6.ps1` runs this):

```powershell
fpc -MObjFPC -Sh -B -FUbuild/cap6/bundler-fpc -FEbuild/cap6/bin `
    -Fusrc/assets -Fusrc/rpc `
    -Fideps/mormot2/src -Fudeps/mormot2/src/core -Fudeps/mormot2/src/lib `
    -Fldeps/mormot2/static/x86_64-win64 `
    tools/bundler/pwebbundle.pas
```

The library behind the CLI is `src/assets/pweb.assets.bundle.pas`
(writer, loader, manifest, SemVer, classification) — headless-tested by
`test/assets/pweb.test.bundle.pas` inside `pwebtests`.
